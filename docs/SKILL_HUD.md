# 스킬 쿨타임 HUD

마인크래프트 Fabric 1.21.4 클라이언트 모드. 서버 액션바에 있는 **스킬명**을 감지하여 등록된 쿨타임을 시작하고, 사용자가 표시하도록 선택한 스킬만 텍스트 HUD에 표시합니다.

## 명령어

- `/sh toggle` — 스킬 HUD 전체 표시 켜기/끄기
- `/sh sword9 sl toggle` — 귀참도 Shift+좌클릭(진혼) 표시 켜기/끄기
- `/sh sword9 sr toggle` — 귀참도 Shift+우클릭(흑익비산) 표시 켜기/끄기
- `/sh sword9 ss toggle` — 귀참도 Shift 두 번(황천쇄도) 표시 켜기/끄기
- `/sh sword9 all toggle` — 귀참도 전용 4개 슬롯(`l`, `sl`, `sr`, `ss`)을 한꺼번에 켜기/끄기. 공유 도약 `r`은 제외
- `/sh global r toggle` — 모든 검에서 공통으로 사용하는 도약 표시 켜기/끄기
- `/sh sword9 r toggle` — 위 공통 도약과 동일
- `/sh list` — 스킬 목록과 현재 선택 상태 확인
- `/sh size 1.5` — 텍스트 배율 설정 (0.5~5)
- `/sh reset` — 개별 스킬 표시 선택 초기화
- `/hud` — HUD 위치 편집 (`/hud reset`은 위치 초기화)

검 번호는 `sword1`~`sword14`입니다. 개별 스킬 슬롯은 `l`, `sl`, `sr`, `ss`, `r`로 구성됩니다.
명령어는 `toggle` 방식이며 진단·강제 테스트·직접 `on/off` 명령어는 더 이상 제공하지 않습니다.

아직 등록하지 않은 검의 스킬은 감지되지 않습니다. 각 트리거는 서버 액션바에 해당 스킬명이 실제로 포함될 때 작동합니다.

## 동작

- 액션바에 스킬 이름이 들어오면 기본 쿨타임 카운트다운을 시작합니다.
- 같은 성공 메시지가 반복 도착해도 동작 중인 타이머를 다시 시작하지 않습니다.
- 동일 액션바에 해당 스킬 이름과 `5초` 혹은 `5s` 같은 남은 시간이 함께 포함되면 그 값으로 보정합니다.
- 검의 표시 이름이 접두어 등으로 변형되어도 액션바 이름이 등록된 스킬 중 유일하면 자동 감지합니다. 여러 검에 중복된 이름이 있고 구분되지 않으면 잘못된 스킬을 추측하지 않습니다.
- 검을 변경해도 시작된 검별 스킬 타이머는 유지되며, 도약은 모든 검에서 한 개의 타이머를 공유합니다.
- HUD에는 **활성화한 스킬 중 남은 시간이 있는 항목만** 표시됩니다. 위치·배율·스킬 선택 설정은 `config/152_hud.json`에 저장됩니다.
- 서버 재접속 시 진행 중인 로컬 타이머는 초기화됩니다.

실제 게임에서의 컴파일/실행 검증은 별도로 필요합니다.

## 실측 쿨타임 보정 및 연속 사용 처리

- 실측에서 보정 없음은 늦고, 1초 보정은 반대로 일찍 종료됐습니다. **만료 시각을 0.65초 앞당기는 임시 보정**으로 변경했습니다. 등록된 명목 쿨타임(도약 8초 등)은 그대로 유지하며, 보정값은 게임 내 재검증이 필요합니다.
- 하나의 액션바 메시지에 서로 다른 스킬 이름이 여러 개 포함되면, 각 스킬의 타이머를 각각 갱신합니다. 짧은 스킬명이 긴 스킬명 안에만 포함되어 있으면 중복으로 인식하지 않습니다.
- 한 메시지에 여러 스킬 이름과 숫자 하나가 섞여 있으면, 해당 숫자를 모든 스킬에 잘못 적용하지 않고 각 스킬에 등록된 쿨타임을 사용합니다.
- 실제 스킬이 서버에서 다시 사용 가능하지만 로컬 타이머가 약간 남아 있는 경우, 스킬 성공 액션바를 놓치지 않도록 만료 직전 0.75초는 새 사용을 허용합니다. 주 쿨타임 동안 동일 성공 메시지가 반복 도착하면 타이머는 재시작하지 않습니다.
- 액션바를 수신하는 경로를 InGameHud 오버레이와 Fabric GAME(overlay=true) 이벤트 양쪽으로 확장했습니다. 두 경로가 같은 메시지를 받더라도 이미 진행 중인 카운트다운을 중복 시작하지 않습니다.
- 리소스팩의 private-use 문자와 제로폭 서식 문자가 스킬명 중간에 삽입되더라도 이름을 인식하도록 Unicode 정규화를 추가했습니다.
- '쿨타임'이라는 단어만 있다는 이유로 성공한 스킬 메시지를 무조건 무시하지 않고, 명시적인 사용 거절 문구가 있는 경우만 제외합니다.
- 서버가 빠른 입력 중 특정 스킬의 성공 액션바를 **아예 보내지 않는다면**, 액션바만 사용하는 클라이언트에서는 그 사용을 확실히 감지할 수 없습니다. 이 경우 별도의 서버 측 사용 확인 이벤트 또는 신뢰 가능한 수신 패킷 확인이 필요합니다.
- 본 보정은 실측 증상을 기준으로 한 최초 값으로, 서버 환경·지연 등에 따라 추가 조정이 필요할 수 있습니다.

## 2026-10 연속 감지 보강

- 0.5초 보정에서 HUD가 조금 늦었다는 사용자 실측 결과를 반영하여 타이머의 만료 시각을 **0.65초 앞당깁니다**. 이것은 임시 경험값이며 서버와 실측 재검증이 필요합니다.
- Minecraft 1.21.4의 네트워크 핸들러에서 수신하는 `OverlayMessageS2CPacket` 및 `GameMessageS2CPacket(overlay=true)`의 본문을 메인 스레드에 직접 전달합니다. 기존 화면/HUD 및 Fabric 이벤트 수신 경로도 유지합니다.
- 중복된 수신 경로에서 **같은 액션바 문자열이 0.15초 이내** 반복 감지되면 한 번만 처리합니다. 서로 다른 스킬명은 처리합니다.
- 리소스팩 문자열에 공백 등이 섞여도 스킬명이 인식되도록 스킬명 비교에는 공백을 제거한 텍스트를 사용합니다.
- 액션바 전체의 첫 숫자를 무조건 해당 스킬 쿨타임으로 사용하지 않고, **스킬명 뒤 32자 이내에서 가깝게 발견되는 양수 초**만 인정하며 명목 쿨타임을 초과하는 값은 무시합니다.
- 실제 서버에서 빠른 연속 스킬 사용 시 사용 성공 메시지가 화면에 뜨는데도 HUD가 누락되는 현상에 대해 여러 가능성을 보완했지만, 수신 패킷 원문이 확보되지 않아 해결 여부는 아직 검증되지 않았습니다.
